LightTrack v3 · UI/UX audit · 6 October 2026

LightTrack records the day well. The UI doesn't yet let you close it.

Reviewed: Timer, Timeline, Projects and SAP export, from the renderer source (src/renderer/index.html, styles/app.css, app.js, timeline.js, settings-view.js) and the plan, ADR 0005 and STATUS. Lenses: the daily job (correct the day, book it), consistency, accessibility and first run. Users: consultants who book, plus someone who approves.

Verdict

The current UI is built around watching time. The first release is built around booking it. None of the four screens has a concept of a day being done: raw activity is listed as if it were an entry, nothing is draft or approved, and SAP export takes whatever is there. The home screen spends most of its space on focus scores, streaks and goals, which the README says LightTrack is not about. The correction tools a consultant would reach for (switch project, merge, edit) are partly broken and fail without telling anyone. Visually the screens are tidy and on-token, but control styles have drifted and the label style fails contrast in both themes.

Fix first
  1. Make the day the unit of work: blocks, derived booking lines, approve (1, 3).
  2. Make every correction either work or say it failed (2).
  3. Replace the dashboard home with the day under review (4, 5).
  4. Collapse four rule forms into one ordered, testable rule list bound to booking codes (8).
  5. Raise label contrast and make every action a real, focusable button (12, 7, 14).

Findings

P0 blocks the first release · P1 hurts daily use · P2 polish. Numbers match the pins on the screens below.
1P0Daily job · Timeline, SAP export
Raw activity is shown as the timesheet
Timeline lists captured activities and SAP export sums them directly. There is no draft, approved or exported state anywhere, so a consultant can't tell what is finished. Plan principle 1 says raw activity is evidence, never an entry.
Fix: time blocks on the left, derived booking lines on the right, and a day status with one approve action (ADR 0005).
2P0Daily job · Timer, Timeline
Corrections fail silently
From STATUS: the project badge switcher calls switchProject (not exposed, guarded, so nothing happens), Merge calls saveActivity (not exposed), Edit wipes tags, Restore reports success while restoring nothing. These are the four actions someone uses to fix a day.
Fix: remove existence-check guards in the renderer; any missing IPC call shows an error toast. Hide controls whose handler isn't there.
3P0Daily job · SAP export
Export has no gate and no exact preview
Pick a period and Export is live. Rows without a SAP code export anyway, hours are unrounded decimals (5.37), and the preview carries Cost Center and WBS, which LT3-201 retires. The preview is a summary table, not the file. History doesn't stop the same week going out twice.
Fix: export only approved lines, show the literal CSV, list checks, record the run (hash, rows) and lock the lines.
4P1Daily job · Timer
Home is a productivity scoreboard
Focus score, 7-day focus, streak, deep-work and break goals, context switches. The README says LightTrack "is not a productivity-scoring" product and LT3-204 says billable is an accounting field, not a score. For the approver audience this reads as monitoring.
Fix: home becomes the Day screen. Move personal stats to an opt-in Reports view, off by default.
5P1Consistency · Timer
The same numbers, three times
Today's total appears in the Today card, Daily summary and (implicitly) the mini timeline. Billable appears as 87% and as 3.6h. Top projects and Time by project list the same three rows side by side. Each repeat costs a scan and suggests they might differ.
Fix: one total, one per-line breakdown, one place.
6P1Daily job · Timeline
Gaps are counted, not fixable
The Gaps card says 0h 37m, but neither the bar nor the list shows where they are or offers "add block" or "mark as break". The bar's track is --paper on a --paper card, so empty hours are invisible, and it clips to 9:00–18:00. Details exist only in hover tooltips.
Fix: render gaps as rows in the block list with inline actions.
7P1Accessibility · Timeline, Timer
Row actions only exist on hover
.activity-actions is opacity:0 until :hover, with no :focus-within. Keyboard users tab onto invisible Edit/Tags/Delete. Delete sits next to Edit with the same weight.
Fix: show actions always (small ghost buttons), put Delete behind Edit.
8P1Daily job · Projects
Four rule forms, seven fields each, free-text project
App, URL, Jira and Meeting rules repeat the same inline form. Project is a text field, so a typo makes a new project (see "acme portal" in the list). At 1280px the fields can't shrink below their intrinsic width and Add/Update are pushed out of the card. Rules have no order, so which one wins is invisible.
Fix: one ordered list, condition type as a select, target picked from booking codes, test result explains precedence (LT3-301).
9P2Consistency · Projects
Project list looks clickable but isn't
Projects render with the .activity class (pointer cursor, hover tint) but have no click handler. "+ New Project" lives in a separate card above the list, and its modal still asks for Cost Center and WBS.
10P2Consistency · all
Controls have drifted from the token rules
The token header says 4px radius on controls. .form-group inputs follow it (paper, 4px, 32px), but .mapping-form and .settings-row inputs are filled, 8px and padded. Buttons come in .solid, .ghost, .btn-small, .btn btn-sm, .range-btn, .pill and bare row buttons. Period buttons on SAP export show no selected state; only a line of accent text does.
11P2Consistency · copy
Copy and number formats vary
Title Case ("Select Period", "All Projects", "Export History") next to sentence case ("Add manual", "SAP export"). Engineering detail on the home screen ("Sampling: 5s"). Durations as 4h 9m, 3.6h, 0h 37m and 5.37. The feed row prints the duration twice.
Fix: sentence case; H:MM in review, decimal only in the export file.
12P1Accessibility · all
Labels fail contrast in both themes
Every .label, section title and table header is 10px uppercase in --ink-faint: #8c8c88 on white is about 3.4:1, on --raised about 3.0:1, and #76766f on dark paper about 4.1:1. All need 4.5:1 at this size.
Fix: labels to --ink-muted at 11px; keep --ink-faint for decoration only.
13P2Accessibility · Timeline, Timer
Billable vs non-billable by hue alone
Cobalt vs mauve, and mauve (#b8afda) is about 2.1:1 on white, under the 3:1 needed for meaningful graphics. There's no legend.
14P1Accessibility · Timer, Analytics
Clickable things that aren't controls
The project switcher is a span.badge, analytics filters are div.pill, rows are divs. None take focus or Enter. Bare Space toggles tracking on the Timer view, which is easy to hit by accident.
15P1First run · SAP export
No first run
The app starts hidden in the tray and opens on a page of zeros. LT3-601 requires retention to be chosen at first run; nothing asks. Employee ID is set on the export screen, booking codes are optional fields on rules, and every unmatched minute lands in General.
Fix: a four-step setup: retention, booking details, booking codes, start.
16OpenApprover
The approver has no place in the product
In the plan, consultants approve their own lines and the first release hands off a CSV. A second-person approval needs a shared system LightTrack doesn't have. The redesign gives the approver a readable summary with each export; anything more is a decision for after Timmy.

Redesign: the first-release flow

Day → Week → Export, plus Rules and first run. Same tokens, rail and type as today so it can land incrementally. Changes to the system itself: labels move to --ink-muted at 11px, one solid and one ghost button, 4px inputs everywhere, real buttons with the focus ring, H:MM durations. Every frame below is live; try assigning the Outlook block and confirming the remote session, then approve. Open the prototype on its own.

Day · replaces Timer and Timeline · fixes 1 4 5 6 7
Blocks on the left are what happened; lines on the right are what gets booked, actual next to rounded. Problems sit on the block they belong to with the fix as the first button. Approve stays disabled until the blocking checks pass; gaps are information, not blockers. Remote sessions are proposed, never auto-approved (plan principle 4).
Week · fixes 1 5
Booking lines by day with each day's status in the header. This is the view that matches what SAP receives, and the one to read before exporting.
Export · replaces SAP export · fixes 3 11 16
The preview is the file. Checks are listed before the button, the run is recorded with a hash (LT3-303), and the receipt carries a plain summary the consultant can send to whoever approves. In the frame below the week isn't approved yet, so export is held.
Rules · replaces Projects · fixes 8 9 10
One ordered list across all condition types. Targets come from the booking-code list, so typos can't create projects. The test explains which higher rule claimed time first. Booking codes move to their own page.
First run · fixes 15
Retention (default 1 year, per the owner decision), Employee ID and rounding, booking codes, then start. The last step states plainly what LightTrack records.

Open questions

  • Does an approver need to approve inside LightTrack, or is the CSV plus summary enough until Timmy? That decides whether finding 16 needs a product change.
  • Do Analytics and the personal goals stay at all? The redesign keeps them out of the main path.
  • Activity-type codes (P0940005 Meeting, P0940010 Administration) and the CSV column set are placeholders until the export profile is defined.
